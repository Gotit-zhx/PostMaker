# 项目当前状态与任务清单

更新时间：2026-10-30

这份文档是项目状态的统一入口，用来记录已经完成的改造、真实体验结果、当前限制和下一阶段优先级。详细的安装与操作步骤仍以[中文操作指南](user-guide.md)为准，部署参数以[部署指南](deployment.md)为准。

## 当前定位

PostMaker · DataRadar 已从一个内容生成脚本发展为面向个人创作者和小型内容团队的内容情报与审核工作台：

```text
RSS / RSSHub / 网页 → DataRadar 采集与整理 → 素材发现
→ persona 生成草稿 → 人工编辑与审核 → 平台适配 / Markdown / HTML / ZIP 导出
```

项目仍是 local-first MVP，适合本地运行、单机部署和小规模试用。系统不会自动登录或发布到第三方平台，最终发布由用户在官方平台完成。

## 已完成的工作

### DataRadar 与采集链路

- 支持 RSS 和可选网页采集，统一写入 SQLite；可选 PostgreSQL、Redis 和 embedding 能力。
- 支持数据源新增、测试、启停、删除和采集状态查询。
- 支持 RSSHub 内网服务，公开 Compose 使用 Redis 缓存且不暴露 RSSHub 端口。
- 增加 URL 安全校验，限制内部地址、非 HTTP(S) 协议、异常端口和不安全重定向。
- 修复 SQLite 查询、趋势接口、采集资源释放、RSS 多媒体字段和配置回退等问题。
- 新用户模板默认关闭本机代理和 Playwright 网页采集，云服务器可以直接使用；需要代理或网页采集时再显式开启。

### PostMaker 工作台

- 支持账号注册、登录、CSRF、防暴力尝试和 SQLite workspace 隔离。
- 支持从素材列表选择内容和 persona，生成待审核草稿。
- 支持标题和 Markdown 正文编辑、修订历史、版本恢复、批准、退回审核和归档。
- 草稿成功落库后标记素材已使用；标记失败不会丢失草稿。
- 支持微信公众号、知乎、小红书、X / Threads、LinkedIn 和通用 Markdown 等发布准备格式。
- 支持复制标题、正文和标签，下载 Markdown、HTML 和 ZIP 发布包。
- 图片策略已明确为复用来源图片，不自动下载或生成图片。

### 前端与文档

- 统一侧边栏、页头、页脚、卡片、空状态、错误提示和响应式布局。
- 完成新手引导、推荐来源、数据源管理、素材发现和草稿审核页面。
- README、操作指南、部署指南、API 文档、路线图和完整链路审计已更新。
- 新增一次真实用户体验文章，记录从 RSSHub 采集到待审核文章的完整结果。

### 真实用户体验

2026-10-30 使用临时账号完成：

1. 注册并登录工作台。
2. 一键启用 `rsshub-solidot` 推荐来源。
3. 启动采集并获得 20 条素材。
4. 选择 `tech-reviewer / 科技评论家` 生成文章。
5. 生成第 2 篇草稿，状态为 `pending_review`，正文约 2544 字符。
6. 临时批准草稿，生成 `generic` 适配稿并导出 ZIP 发布包。
7. 将草稿恢复为待审核状态。

## 当前问题与风险

### P0：上线前必须处理

- 采集任务状态保存在 DataRadar 单进程内存，不能直接扩展为多 worker 或多实例。
- PostgreSQL 仍是单库模型，尚未完成 workspace 字段或 schema 隔离。
- 缺少统一的请求限流、操作审计和失败告警。
- 需要为 PostgreSQL、Redis、pgvector 和真实备份恢复增加 Docker smoke test。
- RSSHub 路由依赖第三方上游站点，可能因改版、限流或下线失效。

### P1：提升可靠性和商业价值

- 增加采集失败重试、单源错误统计、来源健康检查和可视化提示。
- 增加生成运行记录：耗时、token、估算成本、失败原因和模型参数。
- 增加来源证据链和 claim 级别的事实核对提示。
- 增加标题、长度、来源缺失、重复率和风格一致性检查。
- 增加 `mark_used` 查询字段，减少同一素材重复生成。

### P2：团队和平台能力

- 共享 persona、模板、来源库、评论、审批人和权限。
- 后台任务队列、持久化采集状态和并发编辑冲突处理。
- 趋势仪表盘、主题聚类、来源质量分析和离线评测数据集。
- 在官方 API 和平台政策允许的范围内，再评估半自动发布能力。

## 推荐下一步

1. 先完成采集任务持久化状态、失败重试和来源健康检查。
2. 为每次生成保存输入快照、模型、参数、成本和修订结果。
3. 建立 20–50 条真实素材的回归数据集，评估事实一致性、风格匹配和人工修改比例。
4. 找 3–5 位创作者或 1–2 个小团队连续试用两周，再决定是否投入团队协作和托管 SaaS。
5. 在 PostgreSQL workspace 隔离和备份恢复通过验收后，再扩大公网部署规模。
