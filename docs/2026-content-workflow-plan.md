# PostMaker 2026 内容生产闭环改造计划

## 1. 目标

把 PostMaker 从“配置 RSS 后生成 Markdown”的工具，改造成面向个人创作者和小型团队的内容生产工作台：

> 用户不需要理解 RSS、提示词或模型配置，也能从第一次进入网站开始，完成选题发现、文章生成、人工审核和平台发布准备。

第一阶段只承诺“发布准备”，不自动登录或模拟操作第三方平台。用户可以复制文本、下载图片和导出适配文件，再使用平台官方发布入口完成最终发布。

## 2. 目标用户和成功标准

### 目标用户

- 不熟悉 RSS 的个人创作者；
- 需要稳定选题来源的科技、AI、开源和商业内容创作者；
- 需要自托管和数据控制权的小型内容团队。

### 成功标准

新用户第一次进入后，可以在 10 分钟内完成：

1. 选择一个预置内容主题；
2. 启用一个可用的 RSS 或 RSSHub 来源；
3. 完成一次采集；
4. 选择素材和写作风格；
5. 生成一篇待审核文章；
6. 选择目标平台并得到可复制、可下载的发布稿。

验收必须使用真实浏览器和真实 Docker 部署验证，不以单元测试代替完整流程。

## 3. 产品原则

1. **先给结果，再暴露配置**：RSSHub、模型和采集策略放在“高级设置”，首屏只展示可选主题和下一步。
2. **每个自动动作都有状态**：测试、采集、生成和导出必须显示进行中、成功或失败原因。
3. **来源始终可见**：文章保留原始标题、来源 URL、发布时间和采集来源。
4. **人工批准是发布闸门**：生成结果永远先进入待审核，平台适配只接受已批准草稿。
5. **平台适配先做导出**：优先提供复制、Markdown、HTML、纯文本和图片下载，不提前做高风险的自动发布。
6. **低资源优先**：RSSHub 默认使用轻量镜像和 Redis 缓存；浏览器渲染只为明确需要的路由单独启用。

## 4. 目标架构

~~~text
新手引导 / 快速开始
          ↓
预置主题与来源目录
          ↓
RSS / RSSHub → DataRadar 采集 → 全文提取 → 摘要、标签、重要性
                                      ↓
                              素材发现与选题
                                      ↓
                          persona + 平台约束生成
                                      ↓
                              草稿审核与修订
                                      ↓
                复制文本 / 下载图片 / 导出平台适配包
~~~

### RSSHub 部署决策

- 默认采用官方 Docker 镜像并固定版本或 digest，不直接长期维护完整 fork。
- 使用 routes-user 或独立路由模块承载项目专属来源；只有需要修改核心路由时才建立自有镜像。
- RSSHub 只加入内部 Docker 网络，不直接暴露 1200 端口。
- DataRadar 增加 RSSHub 内部地址白名单，普通用户配置的外部 URL 仍执行公网 URL 安全校验。
- Redis 用于 RSSHub 缓存；不默认启用 Chromium/Puppeteer。
- 为 RSSHub 源保存 route、平台、参数和健康状态，避免用户手填难以理解的 URL。

## 5. 面向小白的首屏闭环

### 首屏内容

首屏只展示：

- “开始创作”主按钮；
- 内容主题卡片：AI、科技、开源、产品、商业；
- 写作目标：行业快讯、观点短文、深度文章、教程；
- 可选的“使用我的 RSS”入口；
- 最近生成的草稿和继续编辑入口。

### 引导步骤

~~~text
选择主题 → 选择写作风格 → 选择一条素材 → 生成草稿
     ↓           ↓              ↓             ↓
自动启用来源   persona       来源核对       待审核文章
~~~

用户不需要先知道 RSS 是什么。系统应把 RSS/RSSHub 表述为“内容来源”，提供可用来源卡片、测试状态和一键启用。

## 6. 平台适配范围

第一版只做发布准备，不做第三方账号登录和自动发布。

| 平台 | 第一版输出 | 结构重点 |
| --- | --- | --- |
| 微信公众号 | 富文本 HTML、Markdown、图片包 | 标题、导语、正文层级、引用、封面图 |
| 知乎 | Markdown、纯文本、HTML | 标题、分段、引用、代码块、原文链接 |
| 小红书 | 标题、正文、话题标签、图片清单 | 短段落、重点句、emoji、话题、竖版图片 |
| X / Threads | 单条文本、线程文本、图片清单 | 短句、链接、线程分段、标签 |
| LinkedIn | 纯文本、Markdown | 专业导语、观点段落、链接和标签 |
| 通用 | Markdown、HTML、纯文本、ZIP | 适合作为人工发布和归档文件 |

平台硬限制不能散落在前端代码中，应放在可版本化的 platforms.yaml 或 Python 配置中。每个平台适配器输入已批准草稿，输出统一结构：

~~~json
{
  "platform": "xiaohongshu",
  "title": "...",
  "body": "...",
  "hashtags": ["AI", "开源"],
  "media": [{"path": "...", "role": "cover"}],
  "warnings": ["建议补充 1 张竖版配图"]
}
~~~

## 7. 数据模型和接口

### 第一阶段

- RSSHub 来源目录和 route 参数；
- 新手引导状态；
- 草稿平台适配预览；
- 复制和下载接口；
- 平台警告和缺图提示。

### 第二阶段

- generation_runs：记录模型、persona、耗时和失败原因；
- platform_exports：记录平台、适配版本和导出内容；
- media_assets：记录封面图、插图、来源和生成方式；
- source_presets：记录内置来源、RSSHub route 和启用状态。

### API 方向

~~~text
GET  /api/onboarding
GET  /api/source-presets
POST /api/source-presets/{id}/enable
GET  /api/platforms
POST /api/drafts/{id}/adapt
GET  /api/drafts/{id}/export-package
~~~

## 8. 交付阶段

### P0：计划和基础设施

- 固化本文档；
- 将 RSSHub 加入公开 Compose 的内部网络；
- 增加 RSSHub 配置、健康检查和低资源默认值；
- 增加内部地址白名单；
- 建立来源预置配置。

### P1：新手工作流

- 设计“开始创作”首屏；
- 主题、persona 和来源预置；
- 一键启用来源、采集和生成；
- 空状态、失败状态和可恢复操作；
- 真实浏览器完成首次文章生成。

### P2：平台适配

- 实现统一平台约束配置；
- 实现微信公众号、知乎、小红书、X/Threads、LinkedIn 和通用导出；
- 增加复制、下载、HTML、Markdown 和 ZIP 导出；
- 增加缺少图片、超长、链接位置等警告。

### P3：图文能力

- 先支持用户上传或来源图片；
- 再支持低成本模型生成封面和配图；
- 保存图片来源、版权提示和生成记录；
- 平台适配包内包含图片和发布顺序。

## 9. 明确不做

- 不绕过平台登录、验证码、风控或反爬；
- 不把第三方平台自动发布作为第一阶段验收条件；
- 不把 RSSHub 全量 fork 作为默认部署方式；
- 不强制用户配置 API key 才能浏览、采集和编辑；
- 不为了“看起来智能”隐藏来源和人工审核。

## 10. 偏航检查

每次改造必须回答：

1. 新用户是否更容易完成第一篇文章？
2. 是否减少了 RSS、模型和平台格式方面的认知负担？
3. 是否保留来源和人工审核？
4. 是否适合低算力云服务器？
5. 是否可以通过真实浏览器流程验证？

如果不能同时回答“是”，该改动暂缓。

## 11. 当前实现状态（2026-10-30）

已完成并通过自动化验证：

- 公开 Compose 内置 RSSHub、Redis 缓存和健康检查；RSSHub 只在 Docker 内网可访问。
- DataRadar 对配置的 RSSHub 内部地址执行显式白名单，其他内网地址仍被 SSRF 校验拒绝。
- 工作台提供推荐来源目录和一键启用接口，RSSHub 地址由 `RSSHUB_SOURCE_BASE_URL` 注入。
- 已批准草稿提供微信公众号、知乎、小红书、X / Threads、LinkedIn 和通用 Markdown 适配器。
- 工作台提供平台选择、预览、复制标题/正文、标签提示和配图提示。
- DataRadar 的来源缩略图和 `image_urls` 已传入草稿，第一阶段只复用来源图片。

验证证据：PostMaker 测试 `63 passed, 2 skipped`；前端 `npm run build` 成功；公开 Compose 使用强随机密钥注入后 `docker compose config --quiet` 成功。

仍待完成：真实云服务器上的首次部署演练、周期性来源可用性检查、平台导出文件/图片打包，以及低价模型调用的成本监控。这些工作不改变当前“人工审核后复制发布”的产品边界。
